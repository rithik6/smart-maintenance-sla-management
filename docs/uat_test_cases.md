# User acceptance test scenarios

Use the [Power BI build guide](../powerbi/README.md) and the [SQL and DAX benchmarks](kpi_definitions.md#postgresql-benchmarks-for-power-bi-reconciliation). The results below describe technical verification of the simulated deliverable. Stakeholder sign-off would be a separate step in a real rollout.

| ID | Scenario and steps | Expected result | Evidence or status |
| --- | --- | --- | --- |
| UAT-01 | Load the PostgreSQL schema and seed. Run the data validation script, then inspect model counts in Desktop. | 540 tickets, 24 assets, 12 technicians, one snapshot row, and 181 calendar dates in the report. Seven tickets have blank technician IDs. Foreign keys, lifecycle rules, and timestamp order reject invalid records. | Verified on PostgreSQL 18.6 and the saved PBIX. |
| UAT-02 | Open the report with slicers cleared and run the `All tickets` benchmark. | 540 total, 22 open, 13 overdue, 61.7761% SLA compliance, and 16.9542 h MTTR. | Verified in both saved PBIX models against SQL. |
| UAT-03 | Compare the `June 2026`, `Line B and High`, and `June 2026, Line B, High, Resolved` benchmark rows. | June has 118 tickets and 13 overdue. Line B and High has 42 tickets and 47.6190% compliance. The combined selection has 11 tickets, zero open and overdue, 63.6364% compliance, and 8.3894 h MTTR. | Verified using equivalent DAX filter contexts and PostgreSQL. |
| UAT-04 | Run the `Open status` scenario. | 10 total, 10 open, six overdue, and blank SLA compliance and MTTR. `In Progress` is outside this status selection. | Verified with DAX and SQL. |
| UAT-05 | Run the `January 2026 and Open` scenario. | Zero total, open, and overdue tickets. SLA compliance and MTTR are blank. | Verified with DAX and SQL. |
| UAT-06 | Inspect tickets 535–540 individually. Compare the computed deadline against the closure time or snapshot. | 535 and 540 meet SLA. 536 is a late closure. 537 is due exactly at the snapshot, 538 is one minute overdue, and 539 is due later. Only 538 is flagged overdue. | Verified with SQL seed assertions and a ticket-level DAX query against the saved PBIX. |
| UAT-07 | Clear slicers and inspect the repeated-incident ranking. | Ten assets appear. B-01 Conveyor leads with 64 tickets, followed by C-01 Sealer with 38. Ties use equipment ID. | Verified in the Desktop model against the ordered SQL results. |
| UAT-08 | Inspect the unfiltered overdue worklist. | 13 overdue tickets. Ticket 499 appears first at 86.80 h overdue. The list contains only unresolved tickets whose deadline passed. | Verified in the Desktop model and rendered worklist against SQL. |
| UAT-09 | Select Line B and High on the Overview page. Switch pages, confirm the selections persist, then clear them. | The Equipment page retains Line B and High. Clearing the slicers restores the 540-ticket baseline. | Manually confirmed in Desktop. The Overview showed 42 tickets before the page switch, the Equipment page retained both selections, and clearing them restored 540 tickets. |
| UAT-10 | Seed a local PostgreSQL database. Set `Data Source` to `PostgreSQL` in Desktop, authenticate, refresh, and rerun the six DAX checks. | Five model tables load in Import mode. The report returns 540 tickets, and all six scenarios match SQL. | Verified end to end. Power BI queried the four source objects using the read-only login. The refreshed copy used `PostgreSQL` mode and matched all six SQL benchmarks, the ten-asset ranking, and the 13-ticket overdue worklist. |
| UAT-11 | Reopen `maintenance_dashboard.pbix` directly and inspect both pages. | The report opens on the Operations Overview. Both pages render, and the saved model can run the benchmarks with the bundled snapshot. | Verified in Power BI Desktop. |

For UAT-02 through UAT-05, paste [validate_kpis.dax](../powerbi/validate_kpis.dax) into DAX Query View and compare it with [05_kpi_benchmarks.sql](../sql/05_kpi_benchmarks.sql). The report displays rates and durations at two decimals. The benchmark compares them at four decimals.
